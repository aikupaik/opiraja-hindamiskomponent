Hindamiskomponent · töötav piloot

Hindamiskomponendi tehniline ülevaade

Kolm vaadet samale süsteemile: kuidas moodulid suhtlevad, kuidas tagame töökindluse ning milliste tehnoloogiatega see on teostatud.

1. Arhitektuur

Kasutajaliidesed suhtlevad API kaudu. Arvutus, andmed ja ülesannete genereerimine jäävad eraldatud sisemisteks teenusteks.

Inimene ja õppekeskkond

Õppija

Algatab testi õpiraja kaudu, vastab küsimustele ja näeb personaalset tagasisidet.

Õppejõud

Lisab alusmaterjali ning ülesannete genereerimise reeglid.

Kasutajaliidesed

Testimängija UI

Kuvab õppijale testiküsimused ning tagasiside.

Administraatori UI

Süsteemi haldamine, simulatsioonide käivitamine.

Koordineeriv teenus

Hindamiskomponendi API

Süsteemi „liikluskorraldaja”: kontrollib õigusi, hoiab testi järge ning ühendab kasutajaliidese, andmed ja arvutusmudeli.

Süsteemi sisemised mudelid ja andmed

KST teadmiste ja adaptiivse testimise mudel

Seob õpitavad oskused eeldusseostega, valib järgmise küsimuse ja arvutab tagasiside.

Andmebaas

Hoiab testiseisu, graafistruktuure, tulemusi ja alusmaterjali.

Ülesandepank

Toob vajalikud küsimused õige oskuse kontrollimiseks.

Testigeneraator (LLM)

Supabase Edge Function: puuduvate ülesannete tellimus käivitab uute testiülesannete genereerimise ja lisab need ülesandepanka.

2. Tehniline töökindlus

Piloodi usaldusväärsus ei tugine ainult mudelile: sama oluline on turvaline ligipääs, järjepidev seisund ja kontrollitud teenustevaheline suhtlus.

Ligipääs on rollipõhine

Hindamiskomponendile saab päringuid teha ainult õpiraja teenus kindla võtme abil. Igale õppijale luuakse personaalne testisessioon unikaalse URL-iga.

Vastus salvestub vaid korra

Igal vastusel on oma tunnus. Katkenud ühenduse korral võib sama vastuse turvaliselt uuesti saata, ilma tulemust dubleerimata.

Moodulid on eraldatud

Internetist on nähtav kasutajaliides ja API otspunktid. API, andmebaas ja KST arvutusmudel suhtlevad omavahel süsteemi sisemises võrgus.

Hindamine on jälgitav

Iga testi juurde talletatakse kasutatud mudeli seadistus; süsteem kontrollib teenuste valmisolekut.

3. Tehniline teostus

Iga tehnoloogia on valitud konkreetse vastutuse jaoks, et lahendus oleks arendatav, testitav ja piloodis käitatav.

Kasutajaliidesed

React + TypeScript

Testimängija ja administraatorivaade. Kaasaegsed eraldiseisvad veebirakendused, mis suhtlevad API-ga.

Töövoo juhtimine

Python + FastAPI

Hindamiskomponendi API. Juhib testisessiooni, õigusi, ülesannete valikut ning andmete ja arvutusmudeli suhtlust.

Hindamisloogika

R + Plumber + KST

Sisemine arvutusteenus. Rakendab teadmiste ruumi teooriat ja adaptiivse testimise mudelit.

Andmed ja integratsioon

Supabase / PostgreSQL

Andmebaas ja Edge Functions. Säilitab testid ning käivitab vajadusel testigeneraatori tellimuse.

Ülesannete loomine

TalTech Azure AI

Testigeneraatori LLM. Genereerib tellimuse peale uusi ülesandeid etteantud alusmaterjali ja reeglite põhjal.

Käitus ja turve

Nginx + Docker Compose + JWT

Veebivärav, konteinerid ja ligipääsukontroll. Teenused on eraldatud ning majutatud TalTechi arvutuskeskuses.

Disainiotsus: tehisintellekt aitab luua ülesandeid, kuid testi kulgemist ja tagasiside arvutamist juhib eraldi, deterministlik KST mudel.
